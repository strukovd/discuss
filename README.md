# Discuss — Концепция проекта

**Статус:** Планирование / начало разработки frontend
**Тип:** Mobile-first веб-приложение (SPA/PWA в перспективе)
**Название:** Discuss
**Основная концепция:** Совместное обсуждение идей и принятие решений на основе структурированных аргументов.

## Этапы разработки
- Первый этап — frontend с заглушками данных и взаимодействий.
- Backend приложения будет отдельным сервисом на NestJS; на первом этапе его не реализуем.
- ИИ — следующий этап с отдельным backend-сервисом. В первый этап ИИ-функции не входят.

## Текущий прототип
- Стартовая страница: создание комнаты, вход по ключу и паролю, выбор гостевого имени.
- Страница комнаты: список обсуждений, фильтры по статусу, создание темы, ссылка приглашения.
- Для просмотра заполненной комнаты на главной есть кнопка «Посмотреть пример комнаты» (ключ `team-demo`, пароль `discuss`).
- Комнаты, темы и аргументы сохраняются в `localStorage`, гостевой доступ — в `sessionStorage`. Данные доступны только в этом браузере; обмен между устройствами и real-time пока не реализованы. Пароли в заглушке хранятся открыто — это локальная имитация входа, а не механизм авторизации.
- Операции с данными находятся в `app/services/rooms.ts` и `app/services/discussions.ts`. Локальное хранилище и примеры данных — в `app/services/mocks`. При подключении backend реализация сервисов заменяется на API-вызовы, страницы продолжают использовать их методы.
- Страница обсуждения: описание темы, аргументы за и против, добавление довода с пояснением и ссылкой на источник. На смартфоне стороны переключаются вкладками, на desktop видны рядом.
- Операции с аргументами находятся в `app/services/arguments.ts`; счётчики в списке обсуждений вычисляются по сохранённым доводам. Старые комнаты сохраняются при обновлении прототипа.
- У каждого довода есть раскрываемое обсуждение: плоский список реплик с автором и временем, добавление реплики и счётчик. Операции находятся в `app/services/comments.ts`; реплики сохраняются в локальном хранилище. В завершённых темах доступны только для чтения.
- Пример реплик: демокомната → еженедельное демо → «Против» → довод о времени подготовки → «Обсудить довод».
- Итог обсуждения: решение и обязательное обоснование, автор и дата. После фиксации тема становится доступна только для чтения. Решённую тему можно отправить в архив и вернуть в решённые без потери материалов и смены ссылки. Методы `resolve`, `archive`, `restore` находятся в `app/services/discussions.ts`. Для старых решённых тем без итога можно дописать решение.
- Контраргументы, оценки и голосование пока не реализованы. Следующий рекомендуемый этап после проверки полного frontend-сценария — отдельный backend на NestJS.

## Вдохновение:
- **Kialo** — дерево аргументов «за» и «против», контраргументы, оценка аргументации.
- **Skribbl.io** — мгновенный вход в комнату по ссылке или коду без регистрации.
- **Google Docs** — интерактивное взаимодействие\совместная работа в реальном времени, анонимные участники с забавными именами и аватарами.

## Основная проблема
Во время рабочих обсуждений, особенно в IT-командах, споры часто превращаются в неструктурированный поток сообщений или устных высказываний.

Типичные проблемы:

- Быстрый словестный поток вместо реальных предложений, представленный как аргементы.
- Мнения выдаются за факты.
- Утверждения не подкрепляются источниками.
- Одни и те же доводы многократно повторяются.
- Контраргументы остаются без ответа.
- Решение принимается без фиксации причин.
- Через несколько месяцев никто не помнит, почему выбрали конкретный вариант.

## Цель
Создать удобное пространство, в котором участники могут:
1. Сформулировать идею или проблему.
2. Предложить аргументы за и против.
3. Возражать на конкретные аргументы.
4. Оценивать полезность и убедительность доводов.
5. Использовать ИИ для анализа аргументации.
6. Сравнивать альтернативные решения.
7. Голосовать.
8. Фиксировать итоговое решение и его обоснование.

## Идеи и фичи
### Доступ без регистрации
Вход максимально простой, по аналогии со Skribbl.io.
Пользователь открывает ссылку, выбирает имя и сразу присоединяется к обсуждению.

### Комнаты как основа приложения
Все идеи и обсуждения существуют внутри комнат.
Одна комната - один код (пароль) - несколько идей в контексте комнаты, иначе запоминать код для каждой идеи - геморно.

Код комнаты — пароль для доступа. Ключ (`key`) — строковый идентификатор комнаты, который можно задать вручную, чтобы получить читаемую ссылку вместо случайного идентификатора.

### Сохранение обсуждений
Обсуждение сохраняет свой ключ или ID между посещениями. После принятия решения его можно отправить в архив; при этом оно остаётся в БД под прежним ключом или ID.

### Аргументы и обсуждение
Модель контраргументов и глубина вложенности пока не определены. Глубокое дерево может быть неудобным на смартфоне, но ограничивать аргументацию заранее не хочется.

Рабочая гипотеза — разделить обсуждение довода и список действующих аргументов. Если в ходе обсуждения довод опровергнут, его следует убрать из списка действующих аргументов. Конкретное поведение нужно проверить на прототипе; это пока не окончательное решение.

### Mobile-first
Приоритет — полноценный и удобный интерфейс на смартфоне.
Пока не ясно, нужна ли Desktop-версия, но перекрывать потенциал её добавления не нужно.

### Визуальный стиль
Светлый интерфейс с лёгким векторным стилем. Основной цвет — синий. Векторные иллюстрации уместны там, где помогают интерфейсу, например в пустых состояниях.

### Real-time
Все ключевые действия синхронизируются между участниками в реальном времени.
Добавили новый аргумент - она плавно появилась, без перезагрузки.

Предварительный список для real-time:
- Появление новых идей.
- Добавление аргументов.
- Добавление контраргументов.
- Голосование.
- Обновление рейтингов.
- Изменение статусов.
- Изменение и удаление материалов.
- Вход и выход участников.

### Простота важнее количества функций
Discuss не должен превращаться в сложный корпоративный продукт наподобие Jira.
Важен сценарий:
**Создал комнату → отправил ссылку → участники вошли → начали обсуждать.**

### Гостевые имена
	Регистрации нет, но у каждого участника должно быть отображаемое имя.
	По умолчанию система автоматически генерирует забавное имя из прилагательного и животного.

	Примеры:
	- Мятый Барсук
	- Сонный Лис
	- Серьёзный Пингвин
	- Хитрый Енот
	- Мудрая Сова
	- Уставший Медведь
	- Философствующая Лягушка

	Пользователь может:
	- Оставить предложенное (в placeholder) имя.
	- Изменить его вручную.
	- Сгенерировать другое кнопкой обновления.
### У объекта обсуждения потенциально может быть тип (например: идея, проблема, ..) и статус
### Кнопка "Мнение ИИ" на объекте обсуждения и на аргументе — следующий этап
### Помимо описания обсуждаемой идеии - возможность красивого WYSIWYG или даже типа слайдов презентации, что бы представлять примеры в виде картинок, ссылок и прочего. А что бы не растягивать в длинную статью - вид в стиле презентаций может быть решением.


## Приблизительный пошаговый USE-CASE
> Поскольку пока что планируется система только для внутреннего использования одной командой, даже для создания идеи (по началу) можно обойтись без авторизации.

### Создание объекта обсуждения
1. Появилась идея\спор
2. Зашел на страницу
3. Кликнул создать комнату (если еще нету)
4. Задал пароль (код) комнаты, и указал ключ комнаты (не обязательно)
5. В комнате создал объект спора
6. По клику получил ссылку
7. Разослал участникам

### Вход в чужое обсуждение
1. Получил ссылку приглашение
2. Зашел введя код
3. Можешь голосовать\предлагать,..

Касаемо удаления\решения спора - так как привязки к автору нет - менять может каждый.
Зайдя на главную страницу комнаты можно увидеть плитки и других обсуждений.
